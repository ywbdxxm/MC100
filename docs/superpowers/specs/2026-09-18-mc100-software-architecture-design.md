# MC100 V1 软件架构设计

日期：2026-09-18。状态：开发设计基线，尚未实现或通过实板验证。

配套文档：[开发计划](../plans/2026-09-18-mc100-software-development.md)、[硬件依据与验收矩阵](../../MC100-VALIDATION.md)。产品需求沿用 [硬件设计 §6–10、§13](../../../MC100-HARDWARE-DESIGN.md)；引脚与能力以用户提供的 2026-09-18 原理图、PCB 快照为本次开发依据。

## 1. 目标、现状与范围

MC100 是离线、可穿戴、自动人声录音设备。上电后持续监听，检测到语音时保存此前 2 秒及后续声音，连续静音 15 秒结束，连续录音每 5 分钟轮换文件。录音保存在可取出的 microSD 卡，以标准 PCM WAV 播放；不依赖手机、网络或云服务。

当前 `firmware/` 仍是会倒计时重启的 ESP-IDF hello_world，并非录音固件。本设计不把既有示例构建结果算作 MC100 软件验证。

本次交付架构、可执行开发计划和验收标准，不修改原理图/PCB，不实现或烧录固件。后续先完成无板软件闭环，再进行实板驱动、电气、声学、掉电和续航验证。

V1 不包含：Wi-Fi/BLE、语音识别/转写、扬声器、云同步、OTA、USB 大容量存储、录音压缩、自动删除旧录音、自动格式化、文件加密。USB 仅用于下载和受限诊断。存储加密及下载保护需要独立产品决策；本版 SD 音频为明文，不宣称隐私保护能力。

## 2. 硬件与软件边界

| 项目 | 开发基线 | 软件含义 |
| --- | --- | --- |
| 主控 | ESP32-S3-MINI-1-N8，8 MB Quad Flash，无 PSRAM | 所有实时缓冲必须放得进内部 RAM，禁止依赖 PSRAM |
| SDK | 项目已选择 ESP-IDF v6.1，目标 `esp32s3` | 固定 SDK 修订和工具链，不随环境自动升级 |
| 音频 | ZTS6872SE，PDM DATA GPIO1、CLK GPIO2、SELECT 接地 | I2S0 硬件 PDM→PCM；有效槽位、采样沿仍需实测 |
| SD | SDMMC 1-bit，DAT0 GPIO6、CLK GPIO7、CMD GPIO8 | 初始 20 MHz；40 MHz 只允许通过卡型验证后选择；不使用 SDSPI/80 MHz |
| 卡检测 | GPIO5，外部上拉 | 软件去抖；实际有效电平必须验证 |
| 电池 | GPIO4 / ADC1_CH3，R6=1 MΩ、R7=330 kΩ、C11=100 nF | 校准后换算电压，不把电压直接伪装成准确电量百分比 |
| 指示灯 | GPIO21，高电平点亮 | `GPIO7_LED` 是旧网络名，绝不能用 GPIO7 驱动灯 |
| 电源开关 | SW1 直接控制 LDO_EN | 没有关机通知、软件断电或电源保持；断电可能发生于任意写入点 |
| 电源状态 | PGOOD#/CHG# 没接 MCU | 不实现虚构的充电状态、USB 插入输入或 GEK 按键事件 |
| SD 电源 | 直接接系统 3V3 | 不能用软件给卡断电重启 |
| 调试 | USB GPIO19/20；BOOT=TP3，EN=TP4 | UART0 未引出；默认保留 ROM 下载和 USB Serial/JTAG |

Flash 分区建议：`nvs` 从 `0x9000` 起、大小 `0x6000`；`phy_init` 从 `0xF000` 起、大小 `0x1000`；单 `factory` 应用从 `0x10000` 起、大小 `0x300000`。剩余 Flash 保留，不假装已实现 OTA。通过分区生成器和干净构建检查地址、对齐、镜像大小；不沿用只有 1 MB 应用空间的默认表。

SDK 的 S3 常规启动频率从 80 MHz 开始。原需求的 40 MHz 监听是功耗验证目标，不是已支持的启动配置：v6.1 的 I2S PDM RX 会持有电源管理锁，可能阻止降频。保持驱动锁正确性，测量实际 CPU/APB 时钟后决定 PM 策略，禁止删除锁来制造低频数字。

## 3. 架构选择

选择“可移植 C11 核心 + ESP-IDF 适配层 + 电脑仿真器”。相同状态机、预录、分段、WAV/日志及恢复源文件在电脑和 ESP32 上编译；仅时钟、并发、ADC、I2S、SD/FAT 和控制台由适配层替换。

相比全部直接写在 IDF 任务中，这增加少量接口，但能在板子到货前测试真正的产品逻辑。相比引入完整网络/AI 框架，本方案避免无关依赖和额外 RAM 开销。仿真不能证明 PDM 电气、SD 控制器或真实卡的掉电行为。

```text
                     Main / State（唯一设备状态写入者）
                     │ 控制命令            ↑ 完成/故障事件
                     ▼                     │
I2S0 → Audio：帧组装 → VAD → 预录快照 + 有界 PCM 队列 → Storage
        │                   │                         │
        └── 电平/时序统计 ────┘                         ├─ WAV + CRC 索引
                                                     └─ SDMMC / FATFS
ADC / Card Detect → Monitor → State       Diagnostics ← 只读状态快照

电脑：PCM 输入、虚拟时钟、故障磁盘  ↔ 同一核心 ↔ ESP32：真实驱动
```

### 3.1 代码边界

| 目录（均在 `firmware/` 下） | 责任 | 禁止依赖 |
| --- | --- | --- |
| `components/mc100_core/` | 公共类型、状态机、分段边界、低电策略、配置校验 | FreeRTOS、IDF、文件系统、动态设备访问 |
| `components/mc100_audio/` | 20 ms 帧组装、双预录银行、有界音频流、VAD 适配 | SD、FAT、设备级状态写入 |
| `components/mc100_storage/` | 文件格式、写入事务、CRC、恢复算法；通过 I/O 接口操作文件 | I2S、设备级状态写入、直接依赖 IDF |
| `components/mc100_board/` | 本板引脚、功能能力、板级参数 | 业务状态和录音算法 |
| `components/mc100_platform_espidf/` | 驱动、任务、队列、NVS、USB、时间源 | 复制一份业务算法 |
| `third_party/libfvad/` | 固定版本的经典 WebRTC VAD C 实现 | 自动追踪上游最新分支 |
| `host/`、`tests/` | 同源核心的测试、仿真、故障注入、数据集评估 | 用脚本重写核心后宣称固件已测试 |
| `main/` | 初始化、依赖装配、启动任务 | 巨型业务循环 |

第三方候选为 [libfvad](https://github.com/dpirch/libfvad)，原因是支持 16 kHz / 20 ms / int16 单声道且模型开销小。先锁定版本、许可证并测量 RAM/CPU；保留 LICENSE、PATENTS、AUTHORS。若资源或语音评估不合格，通过 `mc100_vad` 接口替换并重新评审，不静默退化成仅能判断音量的 RMS 阈值。

### 3.2 任务、所有权和阻塞规则

| 任务 | 唯一拥有 | 初始优先级 / 核 / 栈预算 | 等待方式 |
| --- | --- | --- | --- |
| Audio | I2S0、VAD、帧序号、预录银行、音频流生产端 | 20 / 1 / 8 KiB | I2S 读取有界等待；禁止等待 SD |
| State | 设备状态、代次分配、开始/停止/故障决策 | 18 / 0 / 6 KiB | 事件/截止时间，禁止文件 I/O |
| Storage | SDMMC、FAT、预分配文件、写入/恢复、音频流消费端 | 12 / 0 / 12 KiB | 队列通知 + 有超时的驱动调用 |
| Monitor | ADC 采样、卡检测去抖 | 5 / 0 / 4 KiB | 周期通知；只发事件 |
| Diagnostics | USB 命令解析、限速日志 | 3 / 0 / 4 KiB | 无主机时不阻塞其他任务 |

这些为调度起点，不是实测值。正常 LISTEN/RECORD 无忙等，Wi-Fi/BLE 不初始化，LED 熄灭。不得每 20 ms 新建任务、分配堆或输出日志；热路径初始化后不分配内存。ISR 仅给通知/计数，不能做 VAD、CRC、文件操作。

State 输入事件队列 32 项；到 Audio、Storage 的控制队列各 8 项。事件只传状态边沿/命令结果，不逐帧传 PCM。周期电池和统计用最新值覆盖邮箱合并；关键完成通知、故障使用独立 sticky mailbox + notification，即使普通队列满也能被 State 取到。控制入队最多等待 20 ms，失败进入可诊断协议故障，不无限重试。停止命令也必须唤醒正在等数据的任务。

跨任务的数据所有权：Audio 写、Storage 读已提交的队列元素；冻结银行只读直到 Storage 明确释放。适配层使用经验证的 SPSC 发布/获取顺序或固定队列，禁止裸 `volatile` 代替同步。64 位计数跨核读取需要受保护的短快照；不得持锁进行日志、CRC、SD 或等待。

## 4. 音频、预录与人声检测

### 4.1 固定音频参数

| 参数 | 数值 |
| --- | ---: |
| PCM | 16,000 Hz，signed 16-bit little-endian，mono |
| 帧 | 320 个采样 / 20 ms / 640 byte PCM |
| 数据率 | 32,000 byte/s |
| 预录 | 100 帧 / 2 秒 / 64,000 byte PCM |
| 实时队列 | 96 帧 / 61,440 byte PCM；空队列时容量为 1.92 秒 |
| 静音结束 | 连续 750 个非语音帧，即 15 秒 |
| 文件上限 | 15,000 帧 / 300 秒 / 9,600,000 byte PCM，包含该文件的预录 |

驱动可返回不完整帧，组帧器必须累计到 320 samples 才交给核心；超时、DMA 溢出、字节数非采样对齐分别计数。使用从启动起递增的 64 位帧序号和采样位置，不能用任务被唤醒的时间假装采样时序。确认采样率和字节顺序后才能用 PCM 时间推导持续时长。

PDM 初始请求 64 倍下采样，即目标 1.024 MHz；启动先丢弃 2 帧（40 ms）覆盖麦克风资料中的最长 25 ms 稳定时间。SELECT 接地的有效槽位和极性由首板录音及波形确定，不能仅凭音量非零判定正确。

### 4.2 预录银行与无重复交接

采用两个各 100 帧的银行。平时一个滚动记录最近帧，另一个可作为不可变快照。对当前帧先判 VAD；若触发，则冻结**当前帧之前**最多 100 帧，当前帧作为实时队列第一帧，然后切换滚动银行。

例：触发帧序号 100 时，预录是 `[0, 99]`，实时第一帧是 `100`。启动不足两秒时保存已有的帧，不补造历史。每个快照记录 `generation / first_seq / count / bank_id`；只归还一次，打开失败也要归还。Storage 必须先写该会话快照，再写实时流；不得在写快照过程中让 Audio 等待。

Audio 使用 State 预先授予的 generation，在检测到触发时立即固定快照并开始暂存实时帧，然后发布 TRIGGER。State 批准后才允许 Storage 打开录音；拒绝时显式释放该 generation 的银行和队列数据。权限、资源都在触发前准备，不依靠跨任务往返后再回头抓预录。

队列容量含义必须如实：1.92 秒是空队列的理论 PCM 储量；已有积压、快照尚未落盘、关闭和预分配均会压缩余量，不承诺可以承受任意 1.92 秒 SD 停顿。

### 4.3 VAD 与分段

初始算法配置：libfvad mode=2，16 kHz、20 ms；最近 5 帧中至少 3 帧被判语音则触发。这是待调优的软件选择，不是麦克风参数。进入 RECORD 后任意语音帧重置静音累计。State 在 ARM 时授予静音边界停止策略；Audio 将第 750 个连续非语音帧入流后停止该 generation 入流，报告 SILENCE_END 及精确截止序号。Audio 只停止自己的流，不修改设备状态，避免把 State 调度延迟追加为不确定尾巴。

保留原始 PCM，不用自动增益、降噪或门限裁剪改写录音。RMS/峰值/削顶率仅作诊断。先用可授权语音/噪声语料测触发与误报，再用最终装壳和佩戴场景调整；固定算法与数据集后才冻结参数。

连续讲话达到 15,000 帧，由 Storage 在精确采样边界切到已预分配的下一文件。会话 generation 不变、文件 segment_index 增加，下一文件第一帧接前一文件最后一帧，不重新附加两秒预录。音频流不暂停，轮换完成事件只更新统计。

### 4.4 溢出不能伪装成成功

满队列丢弃最新到达帧，锁存该 generation 的首个缺失序号和丢帧计数，立刻停止该会话继续入流；保存此前连续有效前缀，以 `.partial.wav` 和索引 INCIDENT 标记结束原因，再进入 FAULT。正常支持卡型的验收标准仍是零丢帧。

无法写卡时，故障只能留在 RAM/诊断中；不能声称掉电后一定保留最后故障记录。启动恢复生成的文件一律标识 recovered/尾部不确定，避免把来不及持久化的缺口解释为完整成功。

## 5. 状态机与会话协议

### 5.1 设备状态

| 状态 | 进入与行为 | 离开条件 |
| --- | --- | --- |
| OFF | 物理断电，不是可执行的软件状态 | SW1 ON 且供电有效进入 BOOT |
| BOOT | 校验配置/内存/电池，再挂载、恢复、准备文件槽，初始化音频 | 全部就绪且可录音→LISTEN；低电→HOLD；失败→FAULT |
| LISTEN | 持续采样/VAD/滚动预录；正常不写卡，LED off | 合法 TRIGGER→RECORD；低电→LOW_BAT；故障→FAULT |
| RECORD | 内含 OPENING、ACTIVE、ROTATING、CLOSING；持续音频与有界存储 | 静音关闭且 ACK→LISTEN；低电→LOW_BAT；失败收尾后→FAULT |
| LOW_BAT | 不接纳新会话，确定截止帧，停止采集，尝试有限时长的安全收尾 | 所有者确认停止/卸载后→LOW_BAT_HOLD；驱动仍阻塞则 FAULT/看门狗复位 |
| LOW_BAT_HOLD | 停止 PDM/VAD/写卡，周期低功耗检测；LDO 与 SD 仍有电 | 电压恢复并持续满足滞回条件→BOOT；不自动反复写卡 |
| FAULT | 停止新录音，能保存则保留前缀，LED 限速提示与 USB 查询 | 明确恢复条件/诊断重试→BOOT，或物理重启 |

任意状态都可能被 SW1 OFF/供电丢失直接打断，软件没有“保证先关文件再断电”的路径。

### 5.2 正常关闭、迟到事件与重触发

1. State 发 `STOP_CAPTURE(generation)`；Audio 在一个完整帧边界停止该 generation 入流，返回 `CAPTURE_STOPPED(generation, close_through_seq)`。如果此前已因预授权静音边界停止，STOP 为幂等操作，返回原截止序号，不再次推进边界。
2. State 发 `CLOSE_THROUGH`；Storage 处理该 generation 的快照及所有不大于截止序号的已接纳帧，刷数据/索引、修正头、关闭和重命名后返回 `CLOSED`。**发送停止不等于文件已经关闭。**
3. 优雅关闭期间不能先清队列或使旧 generation 全部失效。只拒绝截止之后的错误帧、非当前/非待接纳会话和重复完成；直到 CLOSED 才回收会话上下文。
4. CLOSING 时仍滚动采样。最多允许一个待接纳新会话：State 在 CAPTURE_STOPPED 后授予新 generation；Audio 可冻结空闲银行并把新帧排在旧帧之后。新预录起点取 `max(saturating_sub(trigger_seq, 100), previous_close_seq + 1, available_first_seq)`，避免与刚关闭文件重叠及无符号下溢。未 ARM 的短窗口内 VAD 仍运行并保留一个人声待触发标记；新 ARM 后立即重评持续人声，使用预录覆盖控制往返，不能丢掉只出现一次的触发沿。
5. Storage 先完成旧会话关闭，再消费新会话快照与实时流。最多两个会话上下文、两个银行、一个 96 帧 FIFO；不得建立无限“待录音”链表。银行/槽位不可用或队列溢出时报告明确资源故障，不能假装捕获了触发。

generation 在一次启动内递增；文件同时带随机 boot_id，跨重启不混淆。长整数溢出按不可恢复内部故障处理，不回绕复用。所有 START/CLOSE/RELEASE/ACK 必须携带 generation，文件轮换另带 segment_index。

超时起点：控制 ACK 初值 200 ms、存储打开/关闭 1,500 ms，均是诊断与软件测试参数；必须用支持卡型的最坏延迟重新确认。超时不允许另一任务跨线程强行卸载或释放尚被驱动引用的内存。先锁存故障和停止生产，等待驱动自身超时；失去进展由看门狗复位并留临时文件供下次恢复。

## 6. 文件格式、写入与恢复

### 6.1 文件布局和命名

每段用 `<boot_id>_<generation>_<segment_index>` 标识，独占创建，名字冲突有界重试，不覆盖原文件。不依赖尚不存在的 RTC 日历；可记录启动后单调时间，不能命名成伪造的真实日期。

| 阶段 | 音频文件 | 索引文件 |
| --- | --- | --- |
| 未认领预分配槽 | `<boot_id>_reserve_<counter>.wav.part` | 同名 `.idx.part`，头标 RESERVED |
| 录制 | `<id>.wav.part` | `<id>.idx.part` |
| 正常完成 | `<id>.wav` | `<id>.idx` |
| 已知丢帧/中止 | `<id>.partial.wav` | `<id>.idx`，带原因 |
| 启动恢复副本 | `<id>.recovered.wav` | 原文件/索引保留作依据 |

PCM 文件从 offset=512 开始连续存放，不把 CRC/序号混入音频字节。512 byte 前缀包含 RIFF 12、fmt 24、JUNK 468（其中 payload=460）、data header 8 byte。标准播放器可以跳过 JUNK；最终 RIFF/data 长度只描述有效 PCM，不包含预分配空洞。

索引是固定尺寸、little-endian、显式序列化格式，不直接写 C struct。512 byte 文件头按以下布局实现并用 T04 黄金格式测试锁定：

| 偏移 | 类型/长度 | 字段 |
| --- | --- | --- |
| 0 | 8 byte | magic `MC100IDX` |
| 8 / 10 | u16 / u16 | version=1 / header_bytes=512 |
| 12 | u32 | flags：RESERVED=1 或 CLAIMED=2，不能同时设置 |
| 16 | 16 byte | boot_id |
| 32 | u64 | generation（RESERVED 为 0） |
| 40 / 44 | u32 / u32 | segment_index / sample_rate=16000 |
| 48 / 50 / 52 / 54 | u16 各一个 | bits=16 / channels=1 / frame_samples=320 / reserved=0 |
| 56 | u64 | first_source_sample（RESERVED 为 0） |
| 64 / 68 / 70 / 72 | u32 / u16 / u16 / u32 | max_pcm_bytes=9600000 / record_bytes=64 / reserved=0 / max_records=4096 |
| 76–507 | 432 byte | 全零保留区 |
| 508 | u32 | 前 508 byte 的 CRC |

后续每项 64 byte：

| 偏移 | 类型/长度 | 字段 |
| --- | --- | --- |
| 0 | u32 | record magic，字节序列 `MCR1` |
| 4 / 6 | u16 / u16 | format_version / record_type |
| 8 | u64 | journal_seq |
| 16 | u64 | 相对 PCM 开头的 offset |
| 24 | u64 | first_source_sample |
| 32 / 36 | u32 / u32 | valid_bytes / payload_crc32 |
| 40 | u64 | generation |
| 48 / 52 / 56 | u32 各一个 | flags / detail / reserved（必须为 0） |
| 60 | u32 | 前 60 byte 的 record_crc32 |

record_type 为 BLOCK=1、CHECKPOINT=2、FINAL=3、INCIDENT=4。CRC 使用 CRC-32/ISO-HDLC，`123456789` 校验值 `0xCBF43926`。BLOCK 描述最多 4,096 byte 的连续 PCM；最后一块可不足，长度必须为偶数。CHECKPOINT/FINAL 的 offset 表示累计有效长度、valid_bytes=0、payload_crc32=0；INCIDENT 同样长度为 0，detail 存明确枚举原因。各项 first_source_sample=头中 first_source_sample+pcm_offset/2；flags bit0 表示 incomplete，其余位必须为 0。journal_seq 从 0 连续递增，BLOCK offset 必须紧接已验证前缀。格式定义和解析必须进行版本、越界、序号、CRC、偏移连续性校验。

格式 v1 的结束规则：正常 FINAL 的 flags/detail 均为 0；异常 INCIDENT 的 flags=1，detail 为稳定原因枚举：MIC_IO=1、STORAGE_IO=2、STORAGE_FULL=3、QUEUE_OVERFLOW=4、ADC_INVALID=5、CONFIG_INVALID=6、RECOVERY_REQUIRED=7、INTERNAL_PROTOCOL=8、LOW_BAT_INTERRUPTED=9。FINAL 和 INCIDENT 均为末条记录，之后不能追加；BLOCK/CHECKPOINT 的 flags/detail 均为 0。编码层提供基于已验证头和前缀的连续性验证器，writer/recovery 必须共同使用，不能只检查每条记录的 CRC。

每个索引最多 4,096 项：512 + 4,096×64 = 262,656 byte；5 分钟 PCM 仅需最多 2,344 个数据块，余量供检查点和结束记录。不得在异常输入下无界增长。

### 6.2 预分配、批写、同步和卡满

V1 支持 FAT32 格式的目标 32 GB 卡；未知/不支持的文件系统返回可诊断错误，不自动格式化。启用 FatFs 长文件名，最大至少 128 字符以容纳会话标识及恢复后缀；同步、扇区大小和 LFN 工作区的配置在 host FAT 镜像与目标中保持一致并计入 RAM/栈预算。

启动准备两个文件槽。每槽 WAV 上限 9,600,512 byte，索引上限 262,656 byte，合计 9,863,168 byte；两槽合计 19,726,336 byte。录音使用已有槽；连续录音尽早准备后继槽，不能直到第 300 秒才申请空间。LISTEN 至少保有一个已准备槽；补充槽位安排在 BOOT/RECORD，正常 LISTEN 不持续写卡。

认领预留槽必须先写入完整会话身份/CLAIMED 标志并同步索引，再改名并同步必要元数据，完成后才能写 PCM 或返回 OPENED。重启优先复用经过校验、仍为 RESERVED 且没有录音记录的空槽，不能每次开机遗留两个大空文件；未能证明空闲的槽保留并报告，绝不覆盖不确定录音。有效未用槽的复用与容量变化必须经过 T06 故障测试，不能依赖扩展名猜测。

预分配后的簇内容不保证为零。创建预留槽时必须将整个索引记录区（4,096×64 byte）流式清零并同步，再写有效 RESERVED 头并同步，之后才可列为可认领槽；中途短写/失败不准入。这样恢复遇到未写记录即停止，不会把旧簇中碰巧有效的历史记录与 PCM 拼成“本次录音”。无需为此清零整个 9.6 MB PCM 区；有效性只由本槽初始化过的索引与内容校验确定。

v6.1 本地 FatFs 配置 `FF_USE_EXPAND=0`，因此不能因为头文件声明了 contiguous API 就承诺能链接/连续预分配。实现先使用可验证的可写 `f_lseek` 扩展，核对实际 `f_tell/f_size` 并同步；它预分配簇但不保证连续。如果选其他 API，先提交独立编译、链接和碎片盘测试证据；不改全局 SDK 掩盖问题。

Storage 使用 32 KiB staging，顺序写完整 4 KiB PCM 块。累计满 32 KiB 或距上次检查点达到 1,000 ms 时，将已有完整块写出、检查实际写入长度、同步 PCM，然后追加对应 BLOCK 记录和 CHECKPOINT，再同步索引；不足一块的尾部暂存，关闭时写有效短块。不能把 `write` 返回成功当成已落介质。

这不是“最多丢一秒”的保证：还存在不足一块的尾部、驱动延迟、卡内部缓存及 FAT 元数据风险。同步周期先作为试验值，按卡型功耗、延迟和掉电结果决定。

每次预分配之前检查：分配后空闲空间至少为文件系统总容量的 10% + 1 MiB 应急余量；预分配失败也必须检查短扩展。实际空闲低于 10% 时不接纳新录音，当前录音在已分配空间内尽快收尾并进入 STORAGE_FULL 故障。禁止自动删除旧音频、自动格式化或循环覆盖。

### 6.3 正常关闭和异常恢复

正常关闭顺序：写剩余 PCM → 同步 PCM → 写 BLOCK/FINAL 并同步索引（异常收尾以 INCIDENT 代替 FINAL）→ 截断至有效 PCM 长度、修正 WAV 头并同步 → 截断索引至已用长度并同步 → 关闭两个句柄 → 分别重命名。FAT 的两次重命名不是跨文件原子事务；恢复器必须支持 `.wav` 配 `.idx.part`、`.wav.part` 配 `.idx` 等中间状态。

恢复器在音频任务启动前运行，单文件流式读取、常量 RAM；仅扫描 MC100 命名和 magic 的文件。正常命名成对且头/FINAL/长度一致的历史文件不在每次启动全量重读 PCM；完整历史 CRC 审计交给专用检查工具和 H06。对未完成、命名冲突或不一致候选逐项验证索引及其指向的 PCM CRC，取从开头连续可证明正确的最长前缀；不能用预分配长度、看似正确的 WAV 头或全零尾部推断录音时长。损坏记录之后不拼接后续数据，也不信任未经校验的 offset。

恢复到新 `.recovered.wav` 副本，正确生成 WAV 头；原始 part/索引不删除、不覆盖。空间不足以生成副本、未知版本、索引缺失或起始损坏时保留原件并报告，禁止盲猜音频有效尾部。利用已验证输出及标识保证恢复幂等，不在每次启动重复复制。完全正常且 FINAL 一致的文件可完成未结束的命名步骤；仍需验证目标不存在且身份一致。

启动恢复有 30 秒初始扫描预算、进展心跳和可诊断状态。超时保留现场进入 RECOVERY_REQUIRED，不能一边恢复一边悄悄宣布 LISTEN；USB 离线恢复工具可继续同源算法，预算后续以支持卡容量/文件数测试收敛。

CRC 日志是检测/恢复方案，不是对任意 SD/FAT 掉电的数学保证。除了文件 API 故障，还必须通过扇区级 FAT 故障模拟及真实卡断电试验验证历史文件、目录和索引是否受损。

## 7. 电池、功耗与故障策略

ADC 先使用 ESP-IDF 对应校准方案，再按 `(1,000 + 330) / 330` 换算电池电压；优先保存原始 ADC、校准引脚 mV 和换算 VBAT mV。上电初始等待 150 ms、每 100 ms 取一组有界样本并中值过滤，这是结合分压 RC 的软件起点，需用实测验证稳定性及误差。不能以单个毛刺触发反复停启。

电脑策略测试使用低电 3,600 mV 持续 3 s、禁止继续写入 3,450 mV、恢复 3,800 mV 持续 30 s 的**模拟值**。这些不是电芯/LDO/卡的安全保证，不得原样标成量产阈值。EVT 固件使用清楚标识的试验配置；发布配置必须来自电池电压、系统电源跌落、ADC 误差、卡写峰值和收尾最坏时间的联合验证。

BOOT 先判断低电/ADC 有效性，再执行可能写卡的恢复和预分配。无电池 USB 调试时 ADC 可能为低，不能据 USB 控制台存在自动绕过保护；只允许显式 EVT 台架模式在受控供电下运行诊断，产品自动录音仍遵守电池策略。

LOW_BAT 停止采集与新录音，在可用电压和初始 1,500 ms 预算内尝试完成已接纳前缀。预算或禁止写阈值到达后不再发起新的修头/同步/重命名，不从另一任务强行取消在途 SD 调用；只在所有者确认静止后进入 HOLD，否则保留 FAULT 并由驱动超时/看门狗复位结束阻塞。无法完成时保留 part 供后续恢复。LOW_BAT_HOLD 停止音频、卸载存储，采用定时唤醒策略评估电压；因 SD 仍供电，不能声称物理关机或零耗电。避免低电复位循环反复恢复写卡。

卡检测初始去抖 50 ms；拔卡立即停止新入流并锁存故障，存储 I/O 超时作为第二证据。文件系统只由 Storage 清理；不从 GPIO ISR 卸载。插回卡后需稳定 500 ms、通过受限重新初始化/恢复后才能回 BOOT；若卡无法重新初始化，提示物理开关重启，不承诺软件断电复位卡。

FAULT 细分 MIC_IO、STORAGE_IO、STORAGE_FULL、QUEUE_OVERFLOW、ADC_INVALID、CONFIG_INVALID、RECOVERY_REQUIRED、INTERNAL_PROTOCOL。正常状态无周期闪灯；故障/低电灯语为短时限速提示，USB 输出准确原因。看门狗按任务进展喂养，禁止无条件定时喂狗掩盖卡死。

| 实时队列，帧 + u64 generation | 96×656 = 62,976 byte |

另计：VAD、FAT 缓存、索引批次、队列控制、NVS、USB、IDF/FreeRTOS、静态数据。用 `sizeof` 静态断言确认结构大小；不能将芯片标称 SRAM 全部视为可分配堆。DMA 使用内部 DMA-capable 内存，其余静态/初始化一次分配，关闭会话后不反复重建大缓冲。

初始验收门槛：所有外设/缓冲启用后内部空闲堆 ≥64 KiB、最大连续块 ≥24 KiB、DMA-capable 空闲 ≥16 KiB；各任务最小剩余栈 ≥分配的 25% 且 ≥1 KiB。先做 map/静态内存核算；动态高水位须实板/目标运行确认。未达到时调整有界结构和栈并重测，不偷加 PSRAM 或静默缩短两秒预录。

版本化配置只允许更改有范围约束的 VAD、灯语、诊断和经验证电池参数；引脚、PCM 格式、文件格式版本不能由任意 USB 输入改变。NVS 缺省值、坏值、旧版本分别处理；不能在 NVS 初始化失败时无条件全区擦除。配置更新只在不录音时显式执行，不逐帧提交 Flash。

USB 只读 `status` 输出：固件/SDK/板配置/文件格式版本、reset reason、状态/子状态、generation/segment、音频采样与 VAD 统计、队列当前/峰值/丢帧、SD 写/sync 最长延迟、恢复结果、空闲容量、ADC/校准电压、任务栈/堆、实际 CPU/APB/PM 状态。日志不输出原始语音，不要求连接电脑才能录音。

将 EVT 诊断命令与发布默认能力分开，所有改变采集/存储的测试命令通过 State 调度；拒绝录音期间格式化、擦除、烧 eFuse、直接任意文件读写。首板保留出厂下载相关 eFuse，不在开发流程中自动启用不可逆保护。

## 9. 无板开发与发布门禁

开发顺序和逐项产出见[开发计划](../plans/2026-09-18-mc100-software-development.md)。核心原则：每项先有可失败的测试，再实现，通过后才集成。

| 层次 | 可以证明 | 不能证明 |
| --- | --- | --- |
| 纯 C 单测/属性测试 | 序号、边界、容量、状态、CRC、格式、错误路径 | 真实麦克风、卡、电池、调度 |
| 电脑端到端与扇区故障测试 | 同源逻辑、音频连续性、模拟掉电恢复、FAT 路径 | SD 内部 FTL/缓存、真实电源跌落 |
| 干净 ESP32-S3 交叉构建 | API/配置/分区/链接与静态资源兼容 | 固件能启动或实际音频正确 |
| 实板 EVT/HIL | 下载、采样、卡时延、ADC、功耗、掉电与长期运行 | 未覆盖卡型、电芯和使用场景 |

软件阶段完成命名为 `SW_READY_FOR_EVT`，不是“整机完成”。量产发布需要验收矩阵中的必需实板项目全部有证据，未解决的充电、装配、结构、ESD 风险也不能被软件测试绿灯覆盖。

固定源代码修订、SDK 修订、第三方许可证、配置、分区、测试种子/语料清单、构建及镜像 SHA256。归档 ELF/map/bin/烧录参数和测试报告；报告必须区分 PASS、FAIL、NOT_RUN，禁止用“预计正常”替代结果。
