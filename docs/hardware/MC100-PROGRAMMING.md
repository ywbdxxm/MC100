# MC100 首次烧录与强制下载

核对日期：2026-09-08。本文是基于当日 EasyEDA 读取形成的历史烧录接线记录；当前硬件依据改以仓库 PDF 快照为准。U3 为 ESP32-S3-MINI-1-N8，8 MB Flash，无 PSRAM。

**本板具备 ESP32-S3 原生 USB ROM 下载所需的供电、数据线、GPIO0 和 EN 连接，不需要另加 CH340/CP2102，也不需要先烧入用户固件才能进入 ROM 下载。这个结论以模组出厂默认下载相关 eFuse、正确贴装和正常供电为前提。** 后续实板已完成芯片识别和固件写入哈希校验；当前可配置 product 最近一次复位停在 ROM `DOWNLOAD (boot:0x0)`。状态和剩余门禁见[验证与状态](../MC100-VALIDATION.md)。USB 参考层分割及麦克风钢网问题见 [PCB 复核报告](MC100-PCB-REVIEW.md)，下载接线成立不等于整板已放行。

SMT 只是完成装配。项目已有 EVT USB 台架固件和 product 上电录音实现；当前 product 的实板录音、SD 读卡闭环尚未完成。自动语音触发留在后续路线图。

## 1. 当前下载接线

| 功能 | 现有连接 | 核对结果 |
| --- | --- | --- |
| USB D- | J2 A7/B7 -> USB_N -> R15 22 ohm -> USB_DM_MCU -> U3.23 / GPIO19 | 原理图、PCB 一致 |
| USB D+ | J2 A6/B6 -> USB_P -> R12 22 ohm -> USB_DP_MCU -> U3.24 / GPIO20 | 原理图、PCB 一致，无正负互换 |
| Type-C CC | CC1/R13、CC2/R11，各 5.1 kohm 对地 | 两侧均有独立下拉 |
| 模组供电 | USB VBUS -> BQ24073 IN/OUT -> TLV75733P -> U3.3 / +3V3_SYS | SW1 必须 ON，才使能 LDO |
| BOOT | U3.4 / GPIO0 -> TP3；R9 10 kohm 上拉 3V3 | 默认正常启动，可由夹具拉低 |
| EN / RESET | U3.45 -> TP4；R10 10 kohm 上拉，C13 1 uF 对地 | 可由夹具拉低复位 |
| GPIO46 | U3.44 未连接外设 | 芯片默认内部弱下拉，满足联合下载所需低电平 [S2] |
| UART0 TX | U3.39 / GPIO43 | NC，未引出测试点 |
| UART0 RX | U3.40 / GPIO44 | NC，未引出测试点 |

BQ24073 的 Power Path 支持外部供电时系统在无电池情况下工作 [S4]。因此电池不是进入下载模式的必需条件；USB 电源、线材及 3V3 启动稳定性仍须在首板验证。当前输入固定 USB500 模式，不能据此认为无电池时能承担任意负载峰值。

## 2. 四个底层测试点

| 位号 | 功能 | PCB 中心坐标，mil / y 向上 | 操作 |
| --- | --- | --- | --- |
| TP1 | GND | (1825, 825) | 探针和量测的公共地 |
| TP2 | +3V3_SYS | (1495, 825) | 仅用于测电源，禁止短接到地 |
| TP3 | GPIO0 / BOOT_GPIO | (1410, 740) | 拉低后复位，选择下载模式 |
| TP4 | EN / CHIP_PU | (1825, 890) | 短暂接地后松开，复位芯片 |

四点均在 Bottom，实际铜焊盘直径 30 mil / 0.762 mm；库名中的 0.5 mm 不是当前尺寸。导出的底层阻焊文件包含对应四处直径 0.8636 mm 的开窗，底层焊膏文件为空，测试点不需要贴器件。GPIO0 和 EN 已核对顶层引出、过孔和底层到 TP 的实际铜连接。

表中是 EDA 顶视坐标，不是翻到板背面后的屏幕坐标。操作按实际 TP 位号识别，不凭左右方位猜测。本板没有 BOOT、RESET 按钮，可用测试夹具、探针或临时细线操作；装壳后应保留接触这些点的途径。

## 3. 首次烧录或强制恢复

下载模式是芯片 ROM 中的程序。在硬件复位时保持 GPIO0=0、GPIO46=0，即进入联合下载模式；GPIO0=1 时从 Flash 正常启动。GPIO46 的当前默认弱下拉已经满足要求，不需要另外寻找 GPIO46 短接点 [S2]。

1. 用支持数据传输的 USB-C 线连接电脑，把 SW1 拨到 ON。初次上电先在 TP2 对 TP1 测得稳定的约 3.3 V。
2. 将 TP3 接到 TP1，保持 GPIO0 为低。
3. 将 TP4 也短暂接到 TP1，保持约 0.5 秒后松开 TP4；此时 TP3 继续接地。
4. 等待约 1 秒后松开 TP3。芯片已采样启动配置，不需要一直短接 TP3。[S2] 要求 EN 拉高后启动配置保持至少 3 ms；这里的 1 秒是便于人工操作的余量。
5. 在电脑上选择重新出现的 ESP32-S3 USB 串口。使用支持 ESP32-S3 的 esptool 或乐鑫 Flash Download Tool，先读取芯片信息和 Flash 容量，再按 MC100 固件构建生成的烧录参数写入。工具中芯片选择 ESP32-S3；当前模组为 8 MB Flash、无 PSRAM。
6. 写入并校验完成后，确认 TP3 已松开，再短暂拉低 TP4 后释放，或将 SW1 OFF/ON 一次，使芯片正常从 Flash 启动。

也可在 SW1 为 OFF 时先将 TP3 接地，再拨到 ON，保持约 1 秒后释放 TP3。关键顺序是 **先拉低 BOOT，再上电或释放 EN；不是只在芯片运行中碰一下 BOOT**。

不要把 TP2 当成复位点。不要将 VBUS 的 5 V 接入任何 BOOT/EN/GPIO 测试点。固件文件、分区和烧录地址必须来自实际项目构建，本文没有用猜测的地址生成烧录命令。

## 4. USB 串口和普通 UART 的区别

ESP32-S3 内置 USB Serial/JTAG 控制器提供 CDC 虚拟串口和 JTAG，也支持主机控制复位/进入下载，电脑可直接通过 USB 与它通信 [S3]。正常情况下烧录工具可以自动进入下载；首次调试或自动下载不成功时，使用上面的硬件强制步骤。

运行中的 MC100 固件需要把控制台/日志配置为 USB Serial/JTAG，才可沿当前 USB 连接查看应用日志。不能以“已经能烧录”推定任意固件都会在该端口打印日志。当前 UART0 的 TX/RX 没有连接器或测试点，不能直接插一个普通 USB-TTL 模块作为现成调试入口。

GPIO19/20 应保留给 USB。若应用改变 USB 引脚、控制器或低功耗状态后导致端口消失，可先用 GPIO0+EN 重新进入 ROM 下载；该方法不能修复供电、焊接、USB 走线故障，也不能恢复已被 eFuse 禁用的下载功能。首板调试阶段应保持下载相关 eFuse 的出厂配置。

增加 UART0 TX/RX 测试点和 BOOT/RESET 按钮会方便故障定位，属于可选的调试改进，不是当前原生 USB ROM 下载必须增加的电路。本次没有修改 PCB。

## 5. 首板验证清单

以下是接线复核提出的验证项目；各项当前状态见[验证与状态](../MC100-VALIDATION.md)。

- 首次装配后检查短路、焊接、USB 正反插，测量 3V3 和 EN 上电波形。
- 无电池 USB 供电、所选电池供电、边充边运行分别验证启动与复位，确认无 brownout。
- 验证 USB 枚举、读取芯片/8 MB Flash、写入与校验、断电后启动，不能以一次识别到端口代替完整烧录验证。
- 验证 TP3+TP4 手动进入下载、释放 BOOT 后正常启动，以及应用 USB 日志。
- 烧录成功后独立验证 PDM 音频和 SD 写入；断电文件恢复按后续路线图单独验收。这些功能不属于 ROM 下载测试。
